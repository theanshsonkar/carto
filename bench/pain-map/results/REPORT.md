Generated by `bench/pain-map/analyze.js`. Repository: Carto (this repo), test command `node test/test.js`, 88 suites / 422 tests.

## Verdict (pre-registered rule)

Rule, as given before data: *Compare LEARNED against STATIC-SUITE (the fair baseline). PROMISING if LEARNED detection >= 90% at cost <= 50% of STATIC-SUITE's cost. KILL if STATIC-SUITE's cost is already within 1.5x of LEARNED's, or LEARNED detection < 80%, or building the map is impractical at this repo size. Otherwise INCONCLUSIVE.*

**Verdict: INCONCLUSIVE** (all killed mutants, n = 211). detection 85.3%, cost ratio LEARNED/STATIC-SUITE 0.20.

- Without broad mutants (|fail| > 44): **INCONCLUSIVE** (n = 211). detection 85.3%, cost ratio LEARNED/STATIC-SUITE 0.20.
- Harder test, LEARNED-STRICT under the same rule: **KILL** (all), **KILL** (without broad).
- Practicality: 770 mutant runs took 21.2 min wall on 3 workers (4 CPUs); the map is practical to build at this repo size.
- Scope: one repository, one test file. The strongest possible outcome here is "promising on one repo", not proof.

## Static baselines: how they were built

- Carto import graph from a scratch-copy index built with `runSync` (src/store/sync.js): 162 files, 510 import rows, 267 resolved to an indexed file (52.4%). Unresolved rows: 206 Node builtins, 23 npm packages, 14 other (`${rel}`, `package.json`, `package.json`, `package.json`, `this consumer can`, `package.json`, `package.json`, `ui`).
- Independent check: a Babel scan of src/ finds 256 literal relative `require()` edges to indexed files; 256 of them (100.0%) are in Carto's graph.
- **STATIC-FILE (Carto native)**: test/test.js is not in Carto's index at all (`IGNORE_DIRS` in src/store/sync.js contains `test`), so Carto's blast radius never contains a test file and selects 0 suites for every file. Spot check with `node src/cli/index.js impact <file>` in the scratch copy: `src/store/path-utils.js`: CLI lists 5 dependents, our reading of reverse_deps (<= 5 hops) 5, identical = true, test files listed = 0; `src/bitmap/bitset.js`: CLI lists 45 dependents, our reading of reverse_deps (<= 5 hops) 45, identical = true, test files listed = 0.
- **STATIC-FILE (test.js imports added)**: deviation to give the native idea a fair reading: test/test.js is added as a node whose edges are Carto's own `extractImports` output for it (100 indexed files); it then selects all 88 suites when F is in that closure (unbounded hops). Sampled files NOT in test/test.js's dependency closure: 25 of 129 (`src/acp/agent.js`, `src/acp/prompt.js`, `src/acp/providers/index.js`, `src/acp/tools.js`, `src/agents/validator.js`, `src/cli/check.js`, `src/cli/diff.js`, `src/cli/explain.js`, `src/cli/export.js`, `src/cli/impact.js`, `src/cli/index.js`, `src/cli/load.js`, `src/cli/org.js`, `src/cli/remove.js`, `src/cli/sync.js`, `src/cli/temporal.js`, `src/cli/watch.js`, `src/engine/worker.js`, `src/extractors/filemap.js`, `src/extractors/frontend.js`, `src/extractors/languages/cpp.js`, `src/extractors/languages/csharp.js`, `src/extractors/languages/java.js`, `src/extractors/languages/rust.js`, `src/watcher/watch.js`).
- **STATIC-SUITE**: Babel scan of test/test.js; scope-aware mapping of `require()` bindings (declarators incl. destructuring and `require(..).x`, plus `x = require(..)` assignments), and require calls inside the callback. Relative requires to any indexed file count (this includes `../index.js` and `../bench/...`, not only `../src/...`). Suite selected if a used module equals F or transitively (unbounded) depends on F in Carto's graph. Suites with no module attribution: 1 (`File discovery`), always selected. Callback references only; helper functions and setup code outside `test()` callbacks are not followed (as specified).
- Carto's native blast radius is capped at 5 hops; unbounded closure differs from the 5-hop set for 7 of 162 indexed files.

## Isolation and deviations from the brief

- Each test run executes in a private mount + network namespace (`unshare -m -n`): worker copy bind-mounted, fresh tmpfs on /tmp, HOME on that tmpfs, no network, `CARTO_NO_UPDATE_CHECK=1`. Reason: test/test.js hard-codes `/tmp/carto-test`, which two copies sharing /tmp would race on; this made parallel workers safe without editing the test file. HOME/network isolation keeps mutated init/provider code from touching the real home directory or the network. The baseline is green under this isolation.
- A suite counts as failing if it is marked ✗ **or** passes fewer tests than at baseline (catches suites that silently register fewer tests). Decided before the mutation run.
- Crashes (no suite line printed) and timeouts are excluded from prediction metrics, since fail(m) is unknown for them.
- "Enclosing function" = nearest named enclosing function (`<anon:Lnn>` if only anonymous, `<top>` outside functions); LEARNED-STRICT uses this.
- STATIC-FILE reported twice: Carto-native (literally 0 test files) and with test/test.js's imports added (see above).
- STATIC-SUITE accepts relative requires to any indexed file, not only `../src/...`.
- Learning curve evaluated on killed mutants with >= 4 other killed mutants in the file, so k = 1, 2, 4 share one population.
- "Without broad mutants" removes them from both the evaluated set and the maps.

## Known limitations

- Held-out mutants in the same file are easier to predict than real agent edits: they are small, local, and share call paths with the mutants that built the map. Real edits add new code, change signatures and touch several files.
- Mutants that break module load or a shared fixture fail nearly everything: 0 of 211 killed mutants failed more than half of all suites. Headline metrics are given with and without them.
- One test file with many suites that share module-level fixtures; static suite attribution misses setup code outside callbacks and helper indirection.
- Survived mutants include equivalent mutants (e.g. `true`->`false` on a value no code path observes); survival is an upper bound on true numbness.
- One repository, one seed.

## Post-hoc observations (not part of the pre-registered verdict)

- Of the 31 LEARNED misses, 20 are cold starts: the mutant is the only killed one in its file, so the map is empty. Conditional on >= 1 other killed mutant in the file, LEARNED detects 180/191 (94.2%). This conditioning was not pre-registered and does not change the verdict.
- Killed mutants occur in 81 of 129 sampled files; 47 files had every mutant survive, so a pain map is empty there too (no test feels them).
- The analysis script was dry-run once on a partial result file (first 130 mutants) to check it ran; no operator, sample, predictor or threshold was changed afterwards.
